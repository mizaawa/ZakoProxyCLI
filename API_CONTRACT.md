# Console API contract

All administration endpoints use `/api/`. Session cookie is `zako_session`, HttpOnly, SameSite=Strict. All requests include `X-Console-Path` equal to `location.pathname` (the security entry). Errors are `{ "error": "message" }`. JSON POST/PUT bodies use snake_case.

- GET `/api/bootstrap`: `{initialized:boolean, authenticated:boolean, username:string, turnstile_site_key:string}`. The site key is returned only when Turnstile is enabled.
- POST `/api/setup`, POST `/api/login`: `{username,password,turnstile_token?}` -> session cookie. When Turnstile is enabled, login requires a token verified by Cloudflare.
- POST `/api/logout`
- GET `/api/groups`: array `{id,name,description:string}`. Groups define routing membership and an optional introduction; specific profiles and the default-strategy switch belong to each client API key. Group responses no longer expose `profile_ids` or `default_strategy_enabled`.
- POST `/api/groups`, PUT `/api/groups/:id`: `{name,description?:string}`. The introduction defaults to empty, permits multiple lines, is trimmed at its boundaries and is limited to 2,000 characters. PUT omission preserves it; an explicit empty string clears it. `null` and non-string descriptions are rejected. Legacy group policy fields do not activate new key policies; groups do not configure arbitrary model lists or instructions.
- DELETE `/api/groups/:id` (reject referenced groups)
- GET `/api/accounts`: array `{id,name,endpoint,models:string[],model_mappings:Record<string,string>,group_ids,rpm,concurrency,priority,enabled,protocols,has_api_key,has_proxy,proxy_display,runtime:{active,failures,cooldown_until}}`. `models` contains selected actual upstream model IDs. `model_mappings` maps requested model IDs to actual upstream model IDs. Secrets omitted. Lower priority number wins.
- POST `/api/accounts`, PUT `/api/accounts/:id`: `{name,endpoint,api_key,models:string[],model_mappings:Record<string,string>,group_ids,protocols,rpm,concurrency,priority,enabled}`. Blank `api_key` on update retains the previous secret. `model_mappings` defaults to `{}` when omitted; every target must appear in the account's selected `models`. Each requested model is resolved once, with no recursive or chained mapping; absent a mapping, the requested model ID is used unchanged and must itself be selected in `models`. Model IDs must contain 1-256 bytes without whitespace or control characters. At most 500 selected models and 500 mappings are accepted. Select one or more protocols from `["responses","compact","chat","anthropic"]`; omitted protocols default to `["responses","compact","chat","anthropic"]`. `chat` routes Chat Completions requests to `/v1/chat/completions`; `anthropic` routes Messages requests to `/v1/messages`. Model names do not restrict protocol choice; the relay provider must support that model on the selected protocol. `rpm`/`concurrency` 0 means unlimited.
- Account create/update accepts optional `proxy_url`: omitted/null preserves saved proxy; empty string clears it; nonempty replaces it. Accepts SOCKS5/SOCKS5h with explicit nonzero port, optional username/password (1-255 decoded bytes each), no path except `/`, query or fragment. Whole URLs are encrypted and omitted from responses; `has_proxy` and credential-free `proxy_display` expose status.
- POST `/api/accounts/proxy-test`: `{proxy_url?,account_id?,endpoint?,api_key?,protocols?}` -> `{connected:boolean,ok:boolean,latency_ms:number,upstream_status:number|null,error:string|null}`. Auth required. Saved values can be reused; proxy and upstream endpoint required. Tests unsaved settings without saving, using GET models with 12-second total timeout and no redirects. HTTP rejection means connected but not ok; connection errors are sanitized. Validation errors use HTTP 400. Time includes proxy negotiation, TLS and upstream response headers, not ICMP ping.
- DELETE `/api/accounts/:id`
- POST `/api/models/discover`: `{endpoint,api_key,account_id?,protocols?:string[],proxy_url?:string|null}` -> `{models:string[]}`. Omitting `proxy_url` reuses the saved proxy, an empty string selects default transport, and a nonempty value uses an unsaved proxy. Unknown account IDs are rejected. Account ID enables reusing stored secret and, when protocols are omitted, stored protocols. Selecting `anthropic` uses `x-api-key` and `anthropic-version: 2023-06-01` for upstream discovery; otherwise Bearer authentication is used.
- GET `/api/keys`: array `{id,name,group_id,profile_ids:string[],default_strategy_enabled:boolean,prefix,enabled,created_at,usage:{input_tokens,output_tokens,cached_tokens}}`. These are client relay keys, distinct from upstream provider keys.
- POST `/api/keys`: `{name,group_id,enabled?:boolean,profile_ids?:string[],default_strategy_enabled?:boolean}` -> `{id,key}`. New keys default to enabled, no profiles and default strategy off. IDs are deduplicated and must match a selected actual model from an enabled, available account in the group. Invalid provider bindings or bindings without credentials do not contribute models; alias names alone do not establish support. Unknown/unsupported profiles and overlapping exact-model variants return HTTP 400 without saving. `null` or incorrectly typed policy fields are rejected.
- PUT `/api/keys/:id`: `{name,group_id,enabled,profile_ids?:string[],default_strategy_enabled?:boolean}`. Explicit profile lists use the same validation as creation; `[]` clears them. Omitting `profile_ids` preserves supported selections and prunes unsupported ones in the target group, including after a group switch. Omitting the default switch preserves it; false disables it. Include `enabled` explicitly when editing a disabled key because its input default is true. The console filters supported profiles and deselects overlapping variants. Keys in the same group have independent policies; specific and default text never stack.
- DELETE `/api/keys/:id`
- POST `/api/keys/:id/reveal`: `{key:string}`
- GET `/api/playground/models?key_id=KEY_ID`: `{models:string[]}` for an enabled client relay key with an existing group. The sorted, deduplicated list includes actual model IDs and valid request aliases from enabled, available accounts in that group that support the `chat` protocol. It never includes key secrets. An absent, unknown or disabled key is rejected.
- POST `/api/playground/attachment`: `{name:string,mime_type:string,data_base64:string}` prepares one attachment for a playground message. The basename is trimmed and limited to 120 UTF-8 bytes. Supported images are PNG, JPEG, WebP and GIF with matching file signatures, at most 4 MiB decoded; success returns `{kind:"image",name,mime_type,data_url}`. PDF is at most 2 MiB, must contain 1–30 pages and extractable text at most 100,000 UTF-8 bytes; success returns `{kind:"text",name,mime_type,text}`. UTF-8 `text/plain`, `text/markdown`, `text/csv` and `application/json` files are limited to 100,000 bytes and return the same text shape. Unsupported, invalid or oversized files are rejected. The returned attachment is supplied in a later chat request; this endpoint does not persist it.
- POST `/api/playground/search`: `{query:string}` trims a 1–200 UTF-8 byte query and returns `{query,results:[{title,url,snippet}]}`. The server requests Bing RSS with a 10-second timeout, no redirects and a 256 KiB response limit, then returns up to five HTTP(S) results with cleaned, length-limited text. A provider failure returns 502. Search results are reference data, not instructions, and are supplied explicitly to a later chat request.
- POST `/api/playground` (alias `/api/playground/chat`): `{key_id:string,model:string,messages:[{role:"system"|"user"|"assistant",content:string,attachments?:PreparedAttachment[]}],search_results?:SearchResult[],stream?:boolean,...ChatCompletionsOptions}`. Requires 1–50 messages, a nonempty model of at most 256 UTF-8 bytes, and an enabled client relay key. Only user messages may have attachments, at most five per message and ten images in the conversation; total text is limited to 250,000 bytes. Text attachments become labeled, untrusted text parts; image attachments become Chat Completions image URL parts. Up to five validated search results become an untrusted reference `system` message. The server removes `key_id` and `search_results`, retrieves the selected key secret internally, and passes the normalized request through the existing `/v1/chat/completions` routing, model mapping, key strategy, retries and usage logging. Other Chat Completions options such as `temperature`, `top_p`, `max_tokens` and `stream_options` pass through. A non-streaming call returns the upstream Chat Completions JSON; `stream:true` returns its SSE chunks. No client key secret is returned or required in the browser request.
- All playground endpoints require the authenticated console session and matching `X-Console-Path`. Successful responses set `Cache-Control: no-store`. The search request sends only its query to Bing; chat forwards conversation content and prepared attachments to the configured upstream account selected by the relay.
- GET `/api/providers`: service providers of kind `sub2api` or `newapi`. Each item includes `id`, `name`, `kind`, `base_url`, `auth_mode`, `username`, `user_id`, `price_multiplier`, `notes`, credential-presence flags, connection status, last synchronization time and nullable USD statistics (`balance`, `today_usage`, `total_usage`, `total_recharged`). `total_recharged_estimated` identifies estimates; unknown values remain null. Credentials are encrypted at rest and never returned.
- The first provider is the built-in `official-zayuai`: initial defaults are `name:"杂鱼AI"`, `kind:"sub2api"`, `base_url:"https://www.zayuapi.com"`, `auth_mode:"password"`, `official/is_official/pinned:true` and `readonly:false`. Its name and site URL are fixed: both PUT and POST `/api/providers/test` reject changes to either field with 400. The form disables these two inputs while keeping credentials editable. Before configuration, its status is `not_authenticated`, credentials are absent, and statistics and synchronization time are null. Opening the list does not contact the site or save an empty provider. The entry can be edited using PUT, tested using POST `/api/providers/test` with its ID, and refreshed after credentials are configured; the first PUT saves its configuration under the same fixed ID. Saved configuration and encrypted credentials persist across restarts and are used for statistics, upstream key/group reads, key creation and account import. Until credentials are configured, key/group reads and key creation return 409 with a login-required message before any remote request. DELETE always returns 403 for this pinned official entry. Ordinary providers return all four flags as false.
- POST `/api/providers`, PUT `/api/providers/:id`: save `{name,kind,base_url,auth_mode,username?,password?,access_token?,refresh_token?,token_type?,user_id?,price_multiplier?,notes?}`. Authentication is `password` or `token`. NewAPI token access also requires the numeric user ID. Blank credentials on edit preserve saved values for the same site/type/identity. Saving configuration does not imply a successful upstream login.
- POST `/api/providers/test`: test the same unsaved configuration; optional `id` reuses saved credentials. Optional `turnstile_token` is a one-time browser proof forwarded only to the Sub2API login endpoint; it is neither persisted nor returned. This performs an upstream login or authenticated user lookup and returns statistics without saving the configuration. Successful session tokens remain encrypted in the preflight cache for 600 seconds so saving the same credentials reuses the login; rotations of an existing saved session are persisted.
- POST `/api/providers/auth-requirements`: authenticated `{kind,base_url}` returns `{turnstile_required,turnstile_site_key}` from the site's public configuration. GET `/api/providers/:id/auth-requirements` reads the same public fields for a saved provider. New API returns no Turnstile requirement. No upstream secret is exposed. The site's public key must support the browser's current hostname.
- Official `official-zayuai` also fixes `kind` to `sub2api`: edits and login tests that change its name, URL or platform return 400. Credentials remain editable.
- Sub2API password mode reuses encrypted access/refresh tokens for statistics and key/group operations, renews expired access tokens, and reauthenticates older configurations without sessions when the site's public settings do not require Turnstile. A new password login requiring Turnstile needs a fresh browser proof. No challenge is completed by the relay itself.
- POST `/api/providers/:id/refresh`: authenticate and refresh a saved provider. Failure preserves previous successful statistics and records the error; success returns the updated provider. NewAPI password authentication uses its session cookie and `New-Api-User` header; Sub2API uses its access token. Upstream credential failures do not invalidate the console administrator session.
- DELETE `/api/providers/:id`: delete the local provider configuration. Accounts imported from that provider retain their binding metadata with `provider_missing` status, clear the saved API key and stop participating in routing. Other relay accounts are unaffected.
- GET `/api/providers/:id/keys`: authenticated, fresh upstream lookup returning `{provider_id,endpoint,keys:[{id,name,group_name,group_multiplier,status,available}],synced_at}`. Only key metadata is public. Supports Sub2API paginated API keys with per-user group-rate overrides, and New API paginated tokens with group ratios. Unknown ratios remain null; they are separate from local routing groups and the provider card's recharge multiplier.
- GET `/api/providers/:id/groups`: authenticated upstream lookup returning `{provider_id,groups:[{id,name,multiplier}]}`. Only the upstream user's currently available groups are selectable; optional rate metadata enriches those choices and never adds groups. `id` is a string (numeric Sub2API group ID or original NewAPI group name), and unknown multipliers are null. Reading groups does not create a key.
- POST `/api/providers/:id/keys`: authenticated `{group_id:string}` creates one upstream key after reloading and validating the currently available group. Its name is generated on the server as `【ZakoAI】` plus the original group name; client names are ignored. Returns `{provider_id,created:true,name,group_id}` without secrets or an inferred key ID; the caller refreshes the metadata list. The import UI captures a fresh key-ID snapshot immediately before creation and automatically selects the unique available key added afterward whose server-generated name and group match; pre-existing same-name keys are excluded. Delayed list visibility can be resolved by refreshing again, while ambiguous multiple new matches require manual selection. Sub2API uses POST `/api/v1/keys` with numeric `group_id`. NewAPI uses POST `/api/token/` with the original group and unlimited quota, no expiry, no model/IP restriction, and no cross-group retry. The creation POST is never automatically retried; on failure the caller is told to refresh the key list before retrying because the upstream may already have committed it. Dismissing the creation form sends no POST and has no creation side effect.
- Provider account import: account save, model discovery and proxy test also accept `{provider_id,provider_key_id}`. The server resolves and validates the selected upstream key, owns the endpoint and stores the secret encrypted. New API imports retrieve the full token through its authenticated key endpoint rather than using a masked list value. Nonempty client `api_key` is rejected in binding mode. Public accounts include nullable `provider_binding:{provider_id,key_id,key_name,group_name,group_multiplier,status,last_synced_at}`. Omitting both selection fields on edit preserves and revalidates a saved binding; sending both null detaches it and requires a new API key for previously bound accounts. Changing a provider site or authentication identity marks its bound accounts `provider_changed`, clears the saved key and requires explicit key reselection before routing can resume. Refresh does not automatically resolve an old key ID against a different identity. Concurrent saves reject stale account snapshots rather than overwriting a newer binding or disabled state.
- GET `/api/accounts/:id/provider-binding`: authenticated refresh returning `{account_id,endpoint,provider_binding,available,synced_at}`. Editing an imported account refreshes its bound endpoint, key name, upstream group and ratio. Confirmed deleted, disabled, expired or exhausted keys become unavailable and clear the saved credential; transient upstream failures return an error while preserving the last confirmed binding. Saving rechecks the upstream key. Refresh occurs on edit/manual refresh/save, not continuously in the background.
- Provider cards display CNY as USD multiplied by the configured positive `price_multiplier`; raw statistics stay in USD. Estimated historical recharge is labeled explicitly and is not a payment or billing record.
- GET `/api/settings`: `{security_path,turnstile_site_key,turnstile_enabled,max_retries,failure_threshold,cooldown_seconds,request_timeout_seconds,retention_days}`. The Turnstile secret is never returned.
- PUT `/api/settings`: same object plus optional `turnstile_secret_key`; both Turnstile keys are written to the project `.env` file, and an empty secret clears both keys. Both keys are required to enable it. Security path `""` or e.g. `"console-secret"`. After success frontend navigates to new path.
- POST `/api/settings/turnstile-test`: authenticated connectivity check against Cloudflare Siteverify; it does not save keys and accepts optional keys from the settings form.
- POST `/api/password`: `{current_password,new_password,confirm_password}` -> all sessions revoked, return to login
- GET `/api/updates`: updater configuration, current version, last checked release and persisted job. A configured but unreachable controller returns an `error` field so reconnect polling can continue.
- GET `/api/updates/latest`: check the fixed official repository's latest non-draft, non-prerelease `vX.Y.Z` release.
- Release discovery works without the updater. Concurrent requests coalesce, successful release checks cache for 5 minutes, failures back off 1 minute; `/api/updates` retains the last known release after lookup failure. Authenticated visible console pages check every 15 minutes and synchronize automatic/manual state.
- POST `/api/updates`: strict `{tag,current_password}` starts an asynchronous source build of that latest release. Requires the current administrator password, with five attempts per minute. Wrong password returns 403 without invalidating the session; an active update returns 409. No user-supplied repository, URL, command, or arbitrary ref is accepted. If the local version is newer than the latest release, this synchronizes the deployment to that official release.
- Update response: `{current_version,configured,latest:{tag,version,url,published_at,notes}|null,update_available,job:{id,status,version,started_at,finished_at,message,logs:string[]}|null,error?}`. Times are Unix seconds. Statuses: `fetching`, `building`, `deploying`, `verifying`, `succeeded`, `failed`, `rolled_back`. A same-version source rebuild is supported. Poll `/api/updates` through a brief proxy restart; sessions and settings are persisted in the data volume.
- GET `/api/stats?from=unix_seconds&to=unix_seconds`: `{summary:{input_tokens,output_tokens,cached_tokens,uncached_tokens,total_tokens,cache_hit_rate,rpm,tpm,total_requests,success_rate,avg_latency_ms,cyber_count},daily:[{date,input_tokens,output_tokens,cached_tokens,total_requests,success_count,cyber_count}],recent:RequestLog[],accounts:{total,healthy,cooling},keys:number}`. Rates as percentages 0-100. Recent limited to 100. Dates UTC.
- GET `/api/profile-templates`: authenticated array `{id:string,name:string,source_url:string,source_revision:string,validation:string}[]` with metadata only; no instruction text or model IDs. The 15 IDs are `codex`, `claude`, `grok`, `deepseek`, `glm53`, `gemini`, `doubao`, `workbuddy`, `cursor`, `mimo`, `kimi`, `grok-bot`, `claude-duet`, `chatgpt-dot`, and `meta-muse`. All reference coldcoffee revision `3249afce6b853ff2f2133e016b223db2cf38b087` with `validation:"unverified"`. Template names identify workflows, not guaranteed model API IDs; Cursor/WorkBuddy are client workflows, `mimo` refers to MiniMax rather than Xiaomi MiMo, and upstream Meta Muse uses Gemini.
- GET `/api/profiles`: authenticated array `{id,name,models:string[],instruction:string,model_family:string,metadata?:{source_url:string,source_revision:string,variant:string,validation:string}}[]`. It retains 42 fixed entries for 41 unique exact model IDs (43 entries across their `models` arrays) and appends valid explicit template bindings referenced by saved keys, deduplicated by ID. Existing fixed IDs and model lists are unchanged, including historical Hanshuang, kimi-break, and AI-Jailbreak IDs; all active bodies, display names, and metadata now use coldcoffee templates by family. `metadata.variant` identifies the template ID and `validation` is `unverified`. `models` matches exact actual IDs after mapping; `model_family` is display metadata, not a wildcard. The general default strategy is unchanged, controlled separately, and not an extra catalog item.
- Explicit template bindings use `coldcoffee@{template_id}@{lowercase hex of the actual model's UTF-8 bytes}`. The template must exist and the decoded model must be supported by an enabled, eligible account in the key's group when saving `profile_ids`. Each binding targets exactly one actual model; request aliases do not establish eligibility. Fixed profiles and bindings share exact-model overlap rejection. Any of the 15 templates may be explicitly bound to any eligible actual model; this does not add model availability, enable a profile automatically, or select by family wildcard. The console builds the ID after selecting an actual model and a template. Invalid, unsupported, or overlapping selections return HTTP 400 without saving.
- GET `/health`: `{status:"ok"}`

Dashboard token formatting is presentation-only: `K` at 1,000, `M` at 1,000,000, `B` at 1,000,000,000, `T` at 1,000,000,000,000, with two decimals for compact values. Smaller values remain integers. Statistics API token fields retain original numeric values. The dashboard export button and its client-side export function are removed in v0.11.0; Request Logs JSON export remains available.

## v0.14.0 Profile Compatibility

All 42 existing fixed profile IDs and model lists are retained. Saved key selections stay active and use the latest coldcoffee text; legacy Hanshuang, kimi-break, and AI-Jailbreak IDs do not retain their former bodies. Historical originals and `profiles/coldcoffee-full/legacy.json` remain for provenance and exact legacy-preset recognition. The general default strategy is unchanged. Explicit bindings use the existing `profile_ids` field, so this release requires no database schema migration. Tests cover configuration and protocol behavior; `unverified` does not claim real model effectiveness.

## v0.12.0 Configuration Migration

Opening a legacy store copies each group's saved policy into its existing keys only where the corresponding key field was absent. Explicit `profile_ids:[]` and `default_strategy_enabled:false` remain unchanged. Legacy groups without profile IDs retain only exactly recognized bundled presets; arbitrary custom instructions do not become active. The migration clears group policy fields and persists `key_strategy_schema:1`, so subsequent opens and new keys do not inherit them again. Missing group introductions become empty. Providers, encrypted credentials and account bindings remain in the configuration. Back up the complete data directory and master key before upgrading; a downgrade must restore the matching pre-upgrade data backup.

## Configuration Examples

Create a routing group with an optional introduction:

```json
{
  "name": "Primary",
  "description": "Shared upstream pool\nResponses and Compact models"
}
```

Create an account with selected actual models and a requested-model alias. Replace `GROUP_ID` with the created group's ID:

```json
{
  "name": "Primary upstream",
  "endpoint": "https://upstream.example/v1",
  "api_key": "YOUR_UPSTREAM_API_KEY",
  "models": ["gpt-5.6-sol", "gpt-6-astra"],
  "model_mappings": {"chat-main": "gpt-6-astra"},
  "group_ids": ["GROUP_ID"],
  "protocols": ["responses", "compact"],
  "rpm": 0,
  "concurrency": 0,
  "priority": 0,
  "enabled": true
}
```

After saving the account, create a client relay key. Obtain current profile IDs from `/api/profiles`; the account's actual models must support the selections:

```json
{
  "name": "Primary client",
  "group_id": "GROUP_ID",
  "profile_ids": ["gpt-5.6-sol-v45", "gpt-6-astra-v2-rc1"],
  "default_strategy_enabled": false,
  "enabled": true
}
```

## Public Routing

`profiles/default.md` adapts existing Astra task-execution and continuation mechanisms for multiple models and actual API capabilities. Its 3,844 UTF-8 bytes have provenance in `profiles/default.SOURCE.json`. Fixed model identity, local-runtime assumptions, and mandatory four-artifact output are removed. Client context remains intact; the profile does not claim to override upstream instruction hierarchy.

GET `/v1/models`, POST `/v1/responses`, POST `/v1/responses/compact`, POST `/v1/chat/completions`, and POST `/v1/messages` use a generated proxy key as Bearer or `x-api-key` authentication. The model list includes selected actual models and valid requested-model aliases from enabled, available accounts in the key's group; invalid provider bindings and bindings without credentials are excluded. The upstream endpoint may include `/v1` or omit it. Streaming passes raw SSE. The proxy forwards each API in its original protocol without conversion between Responses, Chat Completions, and Anthropic Messages.

`/v1/chat/completions` selects accounts with the canonical `chat` protocol ID and uses Bearer authentication upstream. It preserves the Chat Completions request/response shape, including existing messages, tool fields, and multimodal content. The strategy selected by the specific-first/default-fallback rules is prepended as a separate `system` message; existing messages and other request fields are retained. JSON usage uses `prompt_tokens`, `completion_tokens`, and prompt cache details. SSE usage and the `[DONE]` completion marker are observed without converting chunks to Responses or Anthropic events.

`/v1/messages` selects accounts with the `anthropic` protocol and preserves the native Anthropic request/response shape, including tools and content blocks. Upstream authentication uses the account's secret as `x-api-key`; `anthropic-version` is forwarded (default `2023-06-01`) and `anthropic-beta` is preserved. The strategy selected by the same client-key policy rules is prepended to `system`, preserving existing strings or text block arrays and their cache controls. Anthropic streaming recognizes `message_stop`, errors, and truncated streams. Usage includes cache read and cache creation tokens in total input; cached tokens count cache reads. It uses the same model mapping, per-account failover, limits, and logging as the Responses routes.

All supported request protocols resolve the original client model independently per eligible account. Group, protocol, and the mapped actual model selected in account `models` must match. The relay sets `model` to that actual ID, prefers a matching profile selected on the authenticated client key, and otherwise applies the default only when that key's `default_strategy_enabled` is true. With neither condition, no strategy is injected. At most one profile applies; specific and default text never stack. The default covers unmatched eligible models inside or outside the catalog and never expands account model/protocol/group eligibility. Responses and Compact prepend `instructions`; Chat Completions prepends a separate `system` message; Anthropic prepends `system` text. Existing client instructions, messages, tools, multimodal content, and other fields are preserved. Every failover starts from the original client request and recomputes mapping/strategy, without carrying or stacking previous-account text.

Cooldown is evaluated against accounts eligible for the current request's group, protocol, and mapped actual model. A single eligible account does not enter cooldown. When every eligible account is cooling down, the scheduler clears cooldown for that pool and resumes polling; the same rule applies if all candidates fail again. Each client request still attempts at most `max_retries + 1` distinct accounts, and RPM/concurrency limits remain in force. Active streams are never replayed after response forwarding starts. Runtime cooldown, failures, RPM, and concurrency remain process-local.

With the configuration above, `{"model":"chat-main","input":"Hello"}` sends `model: "gpt-6-astra"` with only the selected `gpt-6-astra` profile. An unmapped `gpt-5.6-sol` request keeps that model ID and uses only its own selected profile. An unmapped, unselected model makes this account ineligible. The matching rules are identical across all supported protocols; the example account enables only Responses and Compact.

The six optional AI-Jailbreak profiles reference `Baimuking/AI-Jailbreak` commit `8c278b10f47f305546a52d7a0ce044d2c643dc71` under MIT. The GLM and Grok API adaptations contain 2,114 and 2,014 UTF-8 bytes respectively; these are not token counts or verbatim upstream prompts. They retain direct technical delivery, complete output, explicit uncertainty, and context-grounded continuation while using only actual request context/tools. Fixed workspace identities, blanket authorization, hierarchy overrides, unconditional phrase bans, and assumed persistent memory are omitted. `profiles/ai-jailbreak/SOURCE.json` records input/output hashes and assessment decisions; `python scripts/import-ai-jailbreak.py --check` verifies the bundled data offline. Copyright, license, and adaptation notices are retained in `third_party/ai-jailbreak/` and shipped in the container. Upstream and adapted profiles remain unverified for model effectiveness. DeepSeek retains its existing API-compatible profiles because the candidate forces rewritten-request output; GPT, Claude, Gemini, Kimi, and the default profile remain unchanged pending relevant model evidence.

The 27 profiles retaining coldcoffee text are inline Claude, Grok, Gemini, DeepSeek, and GLM configuration, including adapted Skill text; they do not install or execute local Skills/tools. Each match adds approximately 64–66 KB UTF-8. DeepSeek 4.1 Flash uses the 4,748-byte Hanshuang API adaptation from `aimeoa/hanshuang-codex` commit `cf9c1537c2bd4ed8577ed6509ee665a39709d7d4`; `deepseek-v4.1-flash` and `deepseek-4.1-flash` retain their historical profile, while the separate `deepseek-flash` profile reuses the same instruction. Only general task-execution mechanisms from the shared prompt are adapted. `profiles/hanshuang/SOURCE.json` and `third_party/hanshuang/NOTICE.md` record source selection, hashes, and the upstream MIT README declaration with missing root LICENSE. `python scripts/import-hanshuang.py --check` verifies offline. Availability/forwarding do not guarantee model availability, behavior changes, upstream system-instruction precedence, or refusal bypass. READMEs document attribution and license facts.
