# v0.14.4 · 服务商余额与源码部署维护版（预发布）

这是独立选择的透传维护版，不替换主线 `latest`。代理仍转发请求，51 个模型预设 ID、原有精确型号别名和 16 个模板 ID 保留用于兼容配置；本版不打包或注入历史策略正文。控制台不再把单个容器替换成另一个发行渠道的构建。依赖策略注入的现有部署请不要直接切换。迁移前备份原 `.env` 和完整 `/data`（包括 `master.key`）。

- 后台启动即同步已配置的服务商，此后每 5 分钟刷新一次余额、消费和充值数据。关闭控制台不会中断。未配置凭证的渠道跳过；上游出错保留上次成功数据，并在下一轮重试。
- `docker-compose.yaml` 是根目录唯一部署清单。代理与更新器从同一份源码构建。只下载一份 YAML 或只执行 `docker compose pull` 不能更新源码，也不能替换在运行的容器。
- 两个服务的 `/health` 都返回编译进程序的版本。部署脚本还会对照源码、OCI 标签以及运行容器的实际镜像 ID，发现不一致即返回失败。

## 部署

需要 Docker Compose v2+、Git，以及 Python 3.11+（仅一键脚本/版本检查需要 Python）。已有部署必须沿用原项目名、`.env` 及数据卷，不能 `down -v`。默认只监听 `127.0.0.1:1990`。

在与本维护发行渠道关联的 Git 分支上，一键更新并部署：

```sh
python3 deploy.py
```

如果从本预发布的 Source code 压缩包解压，或检出固定标签，使用 `python3 deploy.py --local`（Windows 可用 `py deploy.py --local`）。首次安装才创建 `.env`，不会覆盖现有配置。

手动部署：仅首次安装且尚无 `.env` 时，先从 `.env.example` 创建它，再运行：

```sh
docker compose -f docker-compose.yaml build --pull
docker compose -f docker-compose.yaml up -d --no-build --pull never --wait
```

核验：`python3 scripts/check-release-version.py --running`。两个服务都必须报告 `0.14.4`。发布源码包只含构建所需文件、许可证及维护测试，不带任何本地数据或凭证。
